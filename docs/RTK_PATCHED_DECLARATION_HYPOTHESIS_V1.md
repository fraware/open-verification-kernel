# Lean 4.35 declaration-level replay-free hypothesis — development v1

**Scope:** research-only successor to [#210](https://github.com/fraware/open-verification-kernel/pull/210) and a preliminary mechanism for [#195](https://github.com/fraware/open-verification-kernel/issues/195). All output remains **non-controlling**. No `VALID`, merge authority, production reuse, transport-soundness theorem, or independently measured predictive accuracy is claimed.

## Concrete question

The #210 baseline compares exact bytes of an imported `.olean` module. It necessarily revalidates a separately rebuilt semantically unchanged module and a module containing an unrelated additional declaration. This experiment tests a narrower *hypothesis*: comparing an observed `op` declaration's **native structural type and definition AST** might avoid those two unnecessary revalidations, provided the rest of the historical proof support is unchanged.

The pre-replay adapter is `experiments/rtk/lean_patched_declaration_hypothesis_v1.py`. It first runs the complete #210 baseline input validation, checking the patched executable digest, source certificate, separately checked source witness, exact unproved target statement, target native log, and `.olean` evidence. It then examines source/target native `op` body equality. This is deliberately a different statistic from the target oracle's `Lean.Kernel.check` / `isDefEq` historical proof replay.

The *exact exposed development fixture* permits only explicitly inspected source proof/type/op constant names `Nat`, `Eq`, `Eq.refl` and `op`; structural AST nodes `const`, `app`, `lam`, `forallE`, `bvar`, plus a bounded `sort`; and the concrete universe forms observed in this native fixture. Unrecognized names, binders, metavariables, projections, lets and universes do not produce a conditional candidate. This is a diagnostic whitelist, **not a proof of complete Lean kernel semantic support**. The instance of imported `Nat`, `Eq`, `Eq.refl`, builtin semantics, all local declarations, and the actual loaded environment are not independently authenticated by that whitelist.

## Pre-oracle decision semantics

- `CONDITIONAL_DECLARATION_CANDIDATE`: baseline evidence bindings pass, imported `op` type/body native AST observations agree and the exact fixed fixture's directly inspected constant names fall within the whitelist. This is a **research prediction**, not licensed reuse. A caller cannot treat it as `VALID`.
- `REVALIDATION_REQUIRED`: imported `op` body observations disagree.
- `UNRESOLVED`: native source/target witnesses pass the baseline but the hypothesis cannot safely classify the restricted reference fragment.
- Malformed, contradictory, substituted or unsupported baseline evidence raises an exception, aborting qualification. It cannot silently become an admissible candidate.

Four original #210 controls are retained, with baseline and new decisions **both generated and hashed before** any target historical proof replay:

| Target condition | #210 whole-module baseline | New declaration hypothesis | Exposed target oracle expectation |
| --- | --- | --- | --- |
| Identical `.olean` reused | `CONDITIONAL_IDENTITY_CANDIDATE` | `CONDITIONAL_DECLARATION_CANDIDATE` | `ADMISSIBLE` |
| Identical source rebuilt, differing `.olean` bytes | `REVALIDATION_REQUIRED` | `CONDITIONAL_DECLARATION_CANDIDATE` | `ADMISSIBLE` |
| Changed `op n := 0+n` | `REVALIDATION_REQUIRED` | `REVALIDATION_REQUIRED` | `INADMISSIBLE` |
| Added unrelated declaration | `REVALIDATION_REQUIRED` | `CONDITIONAL_DECLARATION_CANDIDATE` | `ADMISSIBLE` |

These are explicit **expected development** results. Report actual observed results only once the exact-head native workflow succeeds. The original #210 baseline code and outputs are preserved. No target oracle result is a predictor input. Unit tests use synthetic native records and cannot substitute for real Lean execution.

## The unproved kernel-refinement bridge

The inference

```
same recorded theorem/proof AST
AND same observed imported op type/value AST
AND allowed observed constant names
  => actual historical certificate accepted in target Lean kernel
```

is **not established**. The target record is generated by the workflow, not independently authenticated against a complete target `Environment`. Direct references are not a certified complete kernel-semantic dependency closure. Transparent unfolding, universe constraints, inductive/recursor metadata, local contexts, proof-irrelevant/opaque behavior, trusted axioms, checker flags and imported base declarations lie outside the proved boundary. The current comparison is an experimental selective heuristic with an intentionally narrow test surface.

The earlier #199 preservation theorem is proved for a *different finite first-order evaluator*, not actual Lean `Kernel.check`. The #204 actual-kernel theorem applies to equal complete environments, not these changed ones. Neither theorem certifies this candidate.

## Scientific gates before any reuse authority

1. Specify a semantically meaningful Lean certificate fragment with a machine-checked preservation theorem, including the actual inference and conversion rules its certificates use.
2. Establish an independently reviewable extractor/refinement bridge from authenticated target/source environments to every premise of that theorem; fail closed on omitted kernel-relevant state.
3. Independently inspect the exact same historical proof expression under target context; patched source multi-checker acceptance does not independently qualify target transport.
4. Govern issuer provenance, trusted axioms, revocation, expiry and relying policy.
5. Execute #177 independently selected, pre-registered, sealed prospective experiments. Exposed fixture agreement is not a population false-reuse estimate or a release criterion.
6. Measure end-to-end verification acquisition, proof replay, prediction and repair cost. In this fixture, cheap target replay limits the economic significance of avoided rechecking.

The branch is research-only, stacked on #210, unmerged. Do not promote these conditions into OVK's production decision contract. Preserve all historical outcomes and known negative results, including separate-build `.olean` inequality.
