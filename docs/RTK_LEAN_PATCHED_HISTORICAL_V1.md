# Patched Lean 4.35.0 historical certificate replay — development v1

**Research-only successor to draft #206.** Qualification refers only to designated native checker execution. No production reliance authorization, proof of transport soundness or external source/target policy authentication.

## Scope of the experiment

The predecessor #206 established that a fresh Lean 4.35.0 module containing a simple equality theorem passes the complete sandboxed `lake check --paranoid` suite. That is an infrastructure qualification, not migration of an old proof.

This extension reconstructs the **original historical proof source code** in `experiments/rtk/lean_imported_drift_fixtures_v1/` and `lean_context_drift_fixtures_v1/historical_proof.term.txt` in a fresh Lean 4.35.0 Lake project. The imported declaration is `def op (n : Nat) : Nat := n`, and the historical theorem is `theorem historical_claim (n : Nat) : op n = n := Eq.refl n`.

The original 4.14.0 compiled `.olean` and serialized proof bytes are **never** used. The source theorem is checked through `lake check --paranoid` in a sandbox with six checker acceptances, then **its 4.35.0 native kernel Expr AST** is exported from that compiled theorem and bound to source bytes and the patched checker SHA-256. A separate zero-trust Lean process decodes **the same serialized proof AST** and verifies it against the historical claim with `Kernel.check` and `Kernel.isDefEq`, with no theorem imported into that rechecker.

Two target projects are created independently from source text under the same patched version. Both contain the same **unproved target proposition** `op n = n` represented for inspection as `axiom rtk_unproven_target_claim`, not as a target proof. One target reproduces `op n := n`; the other compiles `op n := 0 + n`. Both module `.olean` files are rebuilt under 4.35.0, fingerprinted, and their native claim and definition ASTs are compared to the original patched source. The version-bound source proof, target proposition logs, module bytes, exact binary digest, and an explicitly non-authoritative manifest are sealed **before any historical target proof replay**.

Only subsequently is the exact patched **source proof Expr** loaded from the sealed source payload, decoded inside each new target kernel process, reserialized for identity, and checked with `Kernel.check` and `Kernel.isDefEq`. The expected development controls are:

| Target declaration | Historical proof reuse oracle |
|---|---|
| `op n := n` | `ADMISSIBLE` |
| `op n := 0 + n` | `INADMISSIBLE` |

The protocol treats `ADMISSIBLE` as an **observed native historical proof recheck result in this specified context**, not source issuer authority, verified transport applicability without replay, semantic support completeness, or target statement truth under all models. The source theorem passes the independent multi-checker suite, while the two target replay outcomes are currently obtained by the patched Lean kernel under `--trust=0`; they are *not* independent multi-checker checks of the transplanted proof. The target placeholder is excluded from the target replay driver.

## Integrity and epistemic limits

- Pinned patched version: Lean `4.35.0`, executable SHA-256 `bf8d54e4714cc4b03d3f6bb34c83b7202b87e49c8bfcbff6895c085bb90ceb38`. Both text and the executable checksum are checked.
- A previous `4.14.0` historical proof artifact must never be silently relabeled as patched evidence. All serializations are freshly generated by the patched source checker and explicitly source/target-version-bound.
- The pre-oracle sealed manifest records **no inferred historical applicability**. It compares structural statement and imported-definition observations and states `kernel_context_equivalence_proved=false`, `transport_support_soundness_proved=false`, `provenance_policy_authenticated=false`, and `production_reliance_authorized=false`.
- Native logs, hashes and `lake check` outputs are reproducibility evidence under the designated trusted runner. They are not externally signed provenance or independent checker formal-correctness proofs.
- The imported-module byte snapshot only covers the tiny development fixture. No proof of adequate support extraction for the full Lean kernel has been established, and no general sound transport theorem follows from the examples.
- The negative result refers to **historical certificate incompatibility**. A fresh target proof could prove the same statement in the changed context, which would be a separate claim-evidence object, never permission to reuse the old proof.
- The entire sample is exposed development fixtures. No prospective false-reuse statistics are inferred for independent #177.
